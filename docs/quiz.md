# Quiz 设计

Quiz 的目标不是检查用户能否誊写公式或完成机械计算，而是让用户按费曼学习法，用自然语言把数学内容讲清楚。公式可以作为被解释的对象，但不应成为输入门槛。

## 两种模式

### Chapter Quiz

- 入口：Reader 当前章节的 Quiz 按钮。
- 目标：检查用户对当前章节的即时理解。
- 选题：普通进入时先从当前章节的持久题库选取；题库不足时，先生成并写入数据库，再从题库选取。只有用户明确“重新出题”时才扩充题库。
- 批量生成与展示数量分离：默认一次模型调用补充 6 题、界面从中展示 3 题；API 可分别通过 `generation_count` 和 `count` 调整，两者上限均为 10。
- 题库排序：优先尚未掌握、作答较少、展示较少的题；当前会话刚见过的题在有其他可用题时后置。
- 事实来源：只使用当前章节完整译文，缺失时回退完整原文；Chapter Quiz 不带入章节 Guide 或 Book Guide。
- 题目记录的 `quiz_mode` 为 `chapter`。

### Book Quiz

- 入口：Library 的 Book Quiz。
- 目标：根据 `User.md` 学习画像和近期答题记录选择当前最值得复习的章节、概念和题型。
- 决策层只选择目标，不直接写题；Reader 跳转到目标章节后再基于该章正文生成题目。
- 每次都生成针对当前目标的新题，不从通用章节题库直接复用。
- 个性化证据只用于定向，不应出现在用户看到的题面中。
- 题目记录的 `quiz_mode` 为 `book`。

## 四种题型

每个题型在 `quiz_skill_registry.py` 中拥有独立的生成指令、评估重点、答题提示、rubric 和追问规则。

| `question_type` | 用户要讲什么 | 禁止退化成 |
| --- | --- | --- |
| `concept_explain` | 概念描述什么、关键性质、例子/反例/后果 | 背诵定义 |
| `theorem_understanding` | 关键条件、结论、意义、条件为何需要 | 复写定理公式 |
| `proof_strategy` | 证明起点、关键工具或构造、怎样走到结论 | 补公式、逐行推导、完整形式化证明 |
| `concept_connection` | 两个概念或结果各自的角色、关系方向和分工 | 泛泛列相同点/不同点 |

旧记录里的 `concept_relation`、`reasoning_fill`、`condition_boundary`、`application`、`compare`、`global_structure` 会映射到最接近的新题型，保证历史 Quiz 仍可读取。

## 出题协议

所有题型共享以下硬约束：

1. 一次只问一个连贯的理解目标，题面使用中文。
2. 用户应能用约 2–6 句自然语言作答。
3. 不要求输入公式、计算、补等式、复现符号或书写完整形式化证明。
4. 只能问正文实际支持的概念、定理或证明，不能根据名称臆造内容。
5. 题面必须直接点名正文中的具体概念、命题、证明目标/关键工具或概念对；不得要求用户自己选择“一个概念、定理或证明”，也不能只拿章节标题当锚点。
6. `expected_points` 描述与该正文锚点相关的具体语义要点，不写成通用题型 rubric 或关键词匹配表。
7. `context_refs` 必须包含正文中实际出现的标题、定义/结果名称或有辨识度的原文短语。
8. Book Quiz 必须命中个性化目标，但不得泄露学习画像中的私密证据或直接告诉用户“你哪里薄弱”。

生成结果会经过正文锚点质量检查。解析器接受 `{"questions": [...]}`、顶层数组、Markdown JSON 代码块和夹在简短说明中的 JSON。模型未配置、调用失败、JSON 截断/不合法或只返回“请选择本章中的一个重要证明”一类泛题时，本轮会把具体错误返回给界面且不写入题库，不再使用通用模板冒充正文题。

题型自己的 Prompt 再决定具体问法。例如 `proof_strategy` 明确要求讲证明路线和关键转折，`theorem_understanding` 则要求区分条件、结论和条件作用；两者不共享一段泛化的“出一道数学题”指令。

## 作答与评估

作答框提示用户“用自己的话讲讲，不必输入公式”，Quiz 中不显示普通 Note 的 Cite/Summary/Export 工具。

评估遵循语义而非关键词：

- 接受数学含义准确的日常语言、类比和省略的代数细节。
- 不因用户没有输入公式或没有复述书中原句而扣分。
- 严格检查逆命题混淆、遗漏关键条件、循环证明和误导性类比。
- 反馈先指出一处已经理解的内容，再集中说明一个最重要的缺口。
- 每轮只给一个短追问，引导用户自己修补讲解，不直接倾倒标准答案。

连续回答时，评估接口同时接收本 Quiz 的对话历史。因此用户在追问后补充的内容，会和前一轮讲解合并理解，不会被当成一份孤立答案。

若没有配置可用 LLM，本地逻辑不会用关键词命中假装完成数学语义判断；它会记录回答、标为待完善，并明确提示当前无法可靠评估。

## 数据流

```text
Chapter Quiz
Reader 当前章 -> 读取章节题库 -> 不足则基于正文生成并入库 -> 从题库选题 -> 自然语言回答 -> 语义评估 -> QuizAttempt

Book Quiz
User.md + 近期 QuizAttempt -> 选择章节/概念/题型 -> 跳转 Reader
-> 针对目标生成新题 -> 自然语言回答 + 历史讲解 -> 语义评估 -> QuizAttempt
```

## 学习画像更新

- 学习画像默认关闭，可在应用设置中开启；开启后会产生额外的模型 Token 消耗。
- 画像按书隔离，保存在各自的 `book_user/User.md` 和 `profile_meta.json` 中。
- 用户进入 Reader 或学习页时，系统同步该书的阅读进度并检查新增 Quiz、笔记和用户提问；有新证据时在后台增量更新。
- 多轮对话只提取用户消息，模型回答不作为用户掌握证据。相关章节的「读前 60 秒」只提供知识位置和阅读路径，不单独证明掌握或薄弱。
- 新记录先压缩为章节级摘要，再与旧总结合并；模型不可用或调用失败时保留旧画像和待处理记录，不追加原始证据，也不推进增量游标。
- 阅读难度默认为「未标记」，只有用户主动选择的「困惑」或「困难」会进入进度摘要。

题目保存结构化的语义要点、常见误解、rubric、追问策略和 `quiz_mode`；不保存需要用户照抄的长篇标准答案。
