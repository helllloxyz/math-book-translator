# Math Book Translator 完整使用手册

## 1. 产品工作流

一条完整使用路径是：

1. 配置至少一个 LLM 服务商和默认模型。
2. 导入 Markdown 数学书并检查章节大纲。
3. 启动翻译，等待章节译文和导读生成。
4. 在 Reader 中阅读原文/译文、查看导读并提问。
5. 使用标注、笔记和 Quiz 积累学习证据。
6. 在学习工作区查看 Quiz 评估与学习画像。
7. 定期导出图书包，并由管理员备份数据库和存储目录。

阅读已导入原文不要求模型 API；翻译、导读、Chat、Quiz、标题生成、公式修复建议和学习画像等功能会调用模型并产生服务商费用。

## 2. 第一次使用

启动应用后进入书库首页，打开右上角“偏好设置”。

### 2.1 配置模型服务商

进入“模型与存储”：

1. 在左侧选择服务商。
2. 填写 API Key。
3. 对需要自定义地址的 OpenAI-compatible 服务填写 Base URL。
4. 选择推荐模型，或在支持时填写自定义模型名。
5. 保存设置。

内置目录包含 OpenAI、DeepSeek、Gemini、Anthropic，以及 Kimi、Qwen、GLM、MiniMax、OpenRouter 等 OpenAI-compatible 服务。实际可用模型、价格、区域限制和 API 地址以服务商为准。

API Key 保存在运行应用的服务器文件中，不会显示在设置读取响应里，但文件本身没有加密。公共或多人服务器必须限制系统账户和文件访问权限。

### 2.2 分配不同任务的模型

设置页支持默认模型和任务模型：

- 默认模型：没有单独配置时的回退模型。
- 轻量级任务：导入预检、生成标题、翻译等短任务。
- 生成与编译：阅读导读生成。
- 阅读交互：Chat、Quiz 和学习画像。

只想快速开始时，配置一个默认模型即可。希望控制成本或质量时，再为任务组选择不同模型。删除某个服务商密钥后，指向它的模型配置会失效，需要重新选择。

### 2.3 存储路径

“存储路径”控制服务器保存图书文件的位置。它不是浏览器下载目录。

- 本机使用可保留默认值 `storage`。
- 长期服务器建议使用专用、可备份的绝对路径。
- 修改路径不会自动迁移旧图书；修改前应停止应用并由管理员搬迁数据。

### 2.4 学习画像开关

开启“自动生成学习画像”后，进入阅读时会检查新增的 Quiz、笔记和提问，并在需要时调用模型更新画像。关闭不会影响阅读、翻译和普通 Quiz，但不会自动整理学习证据。

## 3. 准备 Markdown 数学书

### 3.1 推荐结构

应用以 Markdown 标题识别目录和章节：

```markdown
# 第一章 群

本章导言……

## 1.1 群的定义

设 $G$ 是一个集合……

## 1.2 子群

……
```

建议：

- 使用连续、清晰的 `#`、`##`、`###` 层级。
- 不要只靠加粗文本模拟标题。
- 保留标准行内公式 `$...$` 和块级公式 `$$...$$`。
- Mermaid 使用 fenced code block。
- 图片尽量使用相对路径，并与书籍目录一起导入。
- 单个拆分后章节正文不要超过 80,000 个字符。

导入前最好修复跳级标题、重复目录和超长章节。应用会提供本地预检和大纲调整，但清晰的源文件能显著改善拆分、翻译和导读质量。

### 3.2 三种导入方式

点击书库右上角“添加图书”。

#### 上传 Markdown

选择本机 `.md` 文件并上传。适合单文件书籍，也是远程服务器使用时最直观的方式。浏览器只上传选中的 Markdown；其旁边未打包的本地图片不会自动上传。

#### 从路径导入

输入运行后端那台机器可访问的文件或目录路径。目录会优先使用 `full.md`，并可读取 `meta.json`。此方式中的“本地”是服务器本地，不是访问网页的客户端电脑。

目录导入适合包含相对图片资源的准备好书籍目录。确保运行应用的系统账户对路径有读取权限。

#### 导入图书包

上传由本应用导出的 `.zip`。图书包用于迁移或恢复单本书，可以包含源章节、译文章节、导读、阅读画像文件和图片。

不要把任意 ZIP 当作图书包；导入器会校验包结构和路径安全性。

## 4. 导入预检和大纲确认

导入后，应用可能先显示警告或大纲确认界面，而不是立即创建图书。

### 4.1 预检警告

预检会提示超长章节、可疑拆分或结构问题：

- “警告”允许检查后继续。
- “已阻止”表示当前内容超过硬性边界，需回到源 Markdown 调整。
- 如果启用了 `IMPORT_PREFLIGHT_LLM` 且轻量模型可用，还会有可选的模型审阅。

### 4.2 大纲调整

大纲界面可以：

- 选择默认导入深度。
- 为单个标题调整拆分层级。
- 删除目录页等不应成为正文的标题。
- 折叠一级分组，快速检查大型目录。
- 查看标题在原文中的行号和上下文。

层级决定 Reader 左侧树的父子关系，也影响章节文件拆分。确认前重点检查正文是否被过度切碎、目录页是否被当成章节、重要小节是否被合并到错误父级。

## 5. 书库首页

书籍卡片显示当前状态和翻译进度：

- 待翻译：已导入原文，还没有完整译文。
- 翻译中：后台正在处理章节。
- 生成导读：译文完成后正在构建导读。
- 已翻译：可以完整阅读译文。
- 失败：某个后台步骤失败，可进入内容状态页定位并重试。

每本书提供以下入口：

- “继续阅读”：进入 Reader。
- 内容状态：查看章节原文、译文和导读覆盖情况。
- 笔记：查看阅读笔记、Quiz 对话和原文标记。
- Quiz · 学习画像：查看全书学习证据和画像。
- 更多操作：重命名、导出图书包或删除。

删除图书会同时删除章节、译文、导读、笔记和相关存储文件，无法从界面撤销。先导出图书包或做实例备份。

## 6. 翻译和导读

### 6.1 启动翻译

导入后从书籍状态操作启动翻译。系统按章节调用所配置的翻译模型，并持续更新完成数、总数和失败数。

翻译会尽量保持 Markdown 标题、列表、代码块、链接、数学公式、Mermaid 和图片引用。模型输出仍可能破坏少量公式或格式，因此重要教材建议抽查译文。

### 6.2 补全和重新翻译

内容状态页提供：

- 补全缺失译文：只处理没有译文的章节，不覆盖已有成功结果。
- 重新翻译单章：新译文成功写入后才替换旧译文。

单章重新翻译后，依赖旧译文的章节导读会标记为过期，需要重新生成。

### 6.3 导读

导读直接根据章节正文生成，可能包括：

- 章节导读：本章目标、关键概念和阅读顺序。
- 目录导读：同一部分各章之间的关系。
- 全书导读：全书结构和概念依赖图。

完整翻译后可以生成全书导读；内容状态页也可以生成或重生成单章导读。重生成全书导读会覆盖现有导读结果。

## 7. Reader 阅读器

### 7.1 左侧导航树

导航树混合显示章节和生成导读。点击节点切换正文；上一项/下一项遵循当前树顺序。目录层级来自导入时确认的大纲。

### 7.2 原文和译文

阅读区默认显示当前内容。工具栏中的“原文对照”可以打开源文，便于核对术语、公式和证明细节。

渲染器支持 Markdown、KaTeX 数学公式、Mermaid 图表和从图书存储目录重写的相对图片 URL。

若某个公式未正常渲染，先对照源文判断是原文件问题还是翻译问题。支持的章节可调用 LaTeX 修复建议，再确认应用修改；该操作会调用模型。

### 7.3 选择文本后的操作

在正文中选中一段文字，会出现上下文菜单。根据当前位置可执行：

- 针对选中文字提问。
- 把选中文字写入笔记或对话。
- 添加黄色高亮。
- 添加蓝色下划线。
- 移除已有标注。

标注记录文本、位置、内容版本和锚点。译文重生成后文本位置可能变化，应用会尽量通过锚点恢复；大幅改写时仍应人工检查。

### 7.4 章节笔记

打开工具栏“笔记”可以查看当前章节笔记。新建章节笔记适合记录自己的理解；从 Chat 整理的对话笔记则保留上下文和回答。

笔记支持 Markdown 和公式。删除笔记不可撤销；删除标注卡片时，对应原文/译文上的高亮或下划线也会移除。

## 8. Chat 问答

问答可以基于当前章节或选中文本发起。回答以流式方式显示，并使用阅读上下文作为依据。

建议的提问方式：

- “用自己的话解释这个定义，并给一个反例。”
- “这一步证明使用了哪个前提？”
- “比较定理 A 和定理 B 的假设差异。”
- “不要直接给结论，先问我一个检查理解的问题。”

对话中的快捷操作可要求模型紧扣当前文本、展开解释、整理为 Markdown 学习笔记，或根据上下文生成后续问题。

模型回答可能错误。数学结论应回到原文、定义和证明核对，尤其不要把自动回答当成教材勘误或正式证明。

## 9. 快捷输入

书库“偏好设置 → 快捷输入”用于维护常用提示词按钮。每一项包括：

- `id`：唯一标识，只能含字母、数字、下划线和连字符。
- `label`：界面显示名称。
- `prompt`：实际发送给模型的指令。

适合保存“给直觉解释”“逐步检查证明”“整理笔记”等个人习惯。修改会影响后续对话，不会重写历史笔记。

## 10. Quiz

Quiz 采用解释驱动的理解检查，不以选择题记忆为主要目标。问题通常围绕概念解释、定理含义和条件、证明策略、概念连接。

### 10.1 章节 Quiz

章节 Quiz 使用当前章节作为主要上下文。提交自然语言回答后，系统保存尝试并调用模型做语义评估。后续问题会参考历史尝试，减少机械重复。

### 10.2 全书 Quiz

全书 Quiz 会从书中选择目标章节或概念，适合复习跨章节关系。先完成一定阅读和章节 Quiz，再做全书 Quiz，得到的目标通常更有价值。

### 10.3 Quiz 对话

遇到不会的问题时可以进入 Quiz 模式对话，要求提示、澄清或分步追问。为了保留真实学习证据，建议先写出当前理解，再请求帮助。

评估和对话会保存为学习记录，可在“笔记”和“Quiz · 学习画像”工作区查看。

## 11. 学习画像工作区

学习工作区汇总 Quiz 作答和评估、学习笔记数量、用户提问等证据，以及已生成的强项、薄弱概念、常见误区和下一步目标。

画像是模型对已有记录的压缩总结，不替代原始 Quiz 和笔记。证据不足时应把它视为初步建议。关闭自动画像后，已有画像仍可查看，但不会自动吸收新记录。

## 12. 笔记中心

书籍的笔记页面按类别组织：

- 笔记：章节笔记、选择文本笔记和 Chat 整理结果。
- Quiz 记录：Quiz 对话和相关学习记录。
- 标记：高亮和下划线。

卡片可以跳回对应原文或章节。单独打开对话时，页面会根据保存的来源元数据恢复书籍、章节和选区上下文。

## 13. 内容状态与维护

内容状态页用于维护，而不是日常阅读。它提供：

- 原文节点总数和有正文的章节数。
- 译文覆盖率、缺失章节和失败状态。
- 章节/目录/全书导读状态。
- 每章源文、译文、导读和 Quiz 记录概览。
- 补全缺失译文、重新翻译单章、生成单章导读、重生成全书导读。

后台任务执行时不要反复点击同一操作。页面会轮询状态；完成后再处理失败或缺失章节。

## 14. 图书包导出与迁移

在书籍卡片“更多操作”中选择“导出图书包”。导出的 ZIP 适合在实例间迁移单本书、删除前保留可导入副本，或在拥有内容分发权时分享整理结果。

图书包可能包含受版权保护的原文、模型生成译文、个人笔记和学习画像。分享前检查版权、隐私和 API 输出使用条款。模型 API Key 不应包含在图书包中。

图书包不是实例级备份：应用设置、全部书目关系和数据库级状态仍应由管理员按部署文档备份。

## 15. 数据、隐私和成本

### 15.1 可能发送给模型服务商的内容

- 章节正文或译文。
- 选中的文本和相邻上下文。
- 用户问题与对话历史。
- Quiz 回答和历史评估。
- 笔记、提问等学习画像证据。

不要导入或发送无权处理的机密、个人敏感或受限制内容。具体保留和训练政策由所选模型服务商决定。

### 15.2 本地保存的内容

服务器保存数据库、源章节、译文、导读、图片、笔记、Quiz、学习画像、模型配置和密钥。任何能读取这些文件的系统账户都可能访问内容。

### 15.3 成本控制

- 先用少量章节验证模型和提示词。
- 为轻量任务选择更经济的模型。
- 遇到限流时降低翻译并发。
- 不需要时关闭自动学习画像。
- 避免在内容未变化时反复重生成全书导读。

## 16. 常见问题

### 不配置 LLM 能做什么？

可以导入和阅读原始 Markdown、浏览目录以及使用不依赖模型的本地功能。翻译、导读、Chat、Quiz 语义评估、公式修复建议和画像需要 LLM。

### 为什么“从路径导入”找不到我电脑上的文件？

路径由后端解释。远程部署时，它指服务器文件系统；要导入浏览器所在电脑的文件，请使用“上传 Markdown”。

### 为什么图片不显示？

检查 Markdown 是否使用相对路径、图片是否随书籍目录导入，以及文件名大小写是否与 Linux 文件系统一致。单文件浏览器上传不会自动携带相邻图片。

### 为什么有的章节没有翻译？

常见原因是限流、网络超时、模型配置失效或章节过长。进入内容状态页查看缺失项，修复配置后使用“补全缺失译文”。

### 修改模型后旧内容会自动变化吗？

不会。模型设置只影响后续调用。需要变化时明确重新翻译章节或重生成导读。

### 删除书籍还能恢复吗？

界面没有回收站。只能从导出的图书包或管理员备份恢复。

### 为什么学习画像没有更新？

确认画像开关已开启、已经产生新笔记或 Quiz 证据、阅读交互模型配置有效，并等待后台分析完成。
